# DSLRay

Десктопный редактор DSL описания интерфейсов на Qt 6 / QML, C++17.
Основная платформа — Windows 10/11; требуется Qt 6.7+.

## Возможности

- Дерево проекта: создание, переименование, перемещение и удаление файлов и папок.
- Вкладки документов и восстановление предыдущей сессии.
- Редактор JSON: подсветка, логические номера строк, перенос, парные скобки,
  направляющие вложений, автоотступ и форматирование отступов.
- Прозрачный режим с отложенной записью (400 мс) и безопасный режим с черновиками;
  сохранение активного документа — Ctrl+S.
- Навигация от списка `elementName` к коду.
- Светлая/тёмная тема, настройки шрифта, отступов, цветов и профиля.

Доска и панель свойств пока заглушки. Кнопки запуска и сохранения в тулбаре
пока не подключены; для сохранения используйте Ctrl+S.

## Организация кода

| Компонент | Ответственность |
|---|---|
| `ProjectTreeModel` | Ленивое дерево файлов и изменение модели при файловых операциях |
| `ProjectController` / QML `Project` | Открытие проекта, файловые команды, подтверждение удаления |
| `DocumentController` / QML `Docs` | Документы, вкладки, сессия, режим записи и черновики |
| `EditorPreferences` / QML `Preferences` | Шрифт, отступы, подсветка, тема и профиль |
| `JsonHighlighter` | Подсветка JSON и отступ перенесённых строк |
| `CodeEditor.qml` + `EditorText.js` | Интерфейс редактора и чистые текстовые алгоритмы |
| `MenuOverlay.qml` + `Menu*Page.qml` | Оболочка меню и страницы настроек |

Страницы меню создаются при первом посещении и сохраняют состояние при
переключении. Один диалог выбора цвета обслуживает все цвета подсветки.
Номера строк создаются только вокруг видимой области; поиск логической строки
использует бинарный поиск по сохранённым смещениям.

Ключи QSettings и формат черновиков совместимы с версией 0.3. Перед сохранением,
закрытием вкладки, сменой режима и файловыми операциями редактор передаёт
накопленный ввод контроллеру. Запись выполняется через QSaveFile; черновик
удаляется только после успешного сохранения. Ошибки показываются в интерфейсе.

## Сборка

В Qt Creator откройте `CMakeLists.txt` и выберите комплект Qt 6.7+.
Для сборки только приложения можно передать `-DBUILD_TESTING=OFF`.

Пример для установленного Qt 6.11.1 MinGW, PowerShell:

```powershell
$env:PATH = "C:\Qt\Tools\mingw1310_64\bin;C:\Qt\Tools\Ninja;C:\Qt\6.11.1\mingw_64\bin;" + $env:PATH
& C:\Qt\Tools\CMake_64\bin\cmake.exe -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=C:/Qt/6.11.1/mingw_64
& C:\Qt\Tools\CMake_64\bin\cmake.exe --build build --parallel
& .\build\appDSLRay.exe
```

Перед пересборкой закройте запущенный экземпляр из этой папки сборки.

## Проверки

При `BUILD_TESTING=ON` требуется модуль Qt Test. В среде с Qt и MinGW на PATH:

```powershell
& C:\Qt\Tools\CMake_64\bin\ctest.exe --test-dir build --output-on-failure
```

Проверки покрывают:

- сохранение, ошибки записи, восстановление и перенос черновиков;
- совместимость настроек, диапазоны значений и уведомления;
- ленивое дерево, CRUD, недопустимые имена и отсутствие дубликатов при перемещении;
- скобки, экранирование JSON, форматирование, отступы и поиск строк;
- подсветку и жизненный цикл её документа;
- загрузку настоящего QML-интерфейса, страницы меню, смену темы, отложенный ввод
  перед сохранением и файловыми операциями, нумерацию большого документа.

Тесты используют временные файлы и отдельные настройки. Интеграционный QML-тест
работает с offscreen-платформой; для сохранения его снимков можно задать
`DSLRAY_TEST_CAPTURE_DIR`. Он проверяет команды и связи компонентов;
нативные диалоги и жесты drag-and-drop мышью требуют ручной проверки.

Разработческие инварианты и нюансы Qt описаны в [CLAUDE.md](CLAUDE.md).
